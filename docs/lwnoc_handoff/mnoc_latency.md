# MNOC 读写延迟分析（2026-11-08）

对象：`lwnoc/lwnoc_mnoc`（memnoc）当前 RTL。方法：静态阅读 RTL 数寄存器级数。**没有做 RTL 仿真**（用户明确要求不仿真），数字也没有逐项复核。

前提：
- 零负载：FIFO 全空、ready 全为 1、没有仲裁冲突、地址冲突或流控忙。有负载时 FIFO 改走 SRAM 路径，延迟更大，静态分析给不出数值。
- 系统侧和环侧时钟相同且对齐。时钟不同时按慢时钟算，每次跨越还有 0–1 拍相位误差。
- 默认配置：ROB 模式（`MNOC_INIU_SUPPORT_ROB=1`）、`HASH_PIPE_EN=0`、异步 FIFO 同步 2 级。
- INIU 的目标解析结果从模块外部连回来，仓库里没有集成顶层，假设外部是纯组合的。集成时外部若打一拍，要再加上。
- 记号：B = 途经的环缓冲节点数（每个 1 拍），A = 途经的异步桥数（每个约 6 拍）。经过环站点和 Start Point 不花时间。

## 结论

- **读**（AR → 第一个 R，不含存储器）：单拍 **54 + 2B + 12A + L_mem**。4 拍突发再晚 3 拍（INIU 要收齐整段突发才发第一个 R）；路上有环缓冲再晚 5 拍（环缓冲让连续数据拍只能隔拍通过）。示例拓扑（npu_mnoc_example 旧的生成结果）最近一对约 57 拍，最远一对（l2dma → ocm_tniu0，1 个环缓冲 + 1 个异步桥）约 73 拍。
- **写**（AW → B，不含存储器）：单拍 **107 + 4B + 24A + L_mem**；4 拍突发约 113（最近）到 143 拍（最远）。写数据离开 INIU 之前，光申请写缓冲号（DBID）的来回就要约 45 拍。
- OOO 模式（`SUPPORT_ROB=0`）读约 **43 + L_mem**：INIU 读请求只要 8 拍、数据逐拍转发。

## 拍数花在哪里

1. **跨时钟**：读跨 4 次、写跨 8 次，每次约 4 拍，约占读延迟三成。同频也省不掉。
2. **ROB 模式**：拆分器 5 拍；读数据收齐整段突发再发。
3. **FIFO 没开直通**（`FORWARD_EN=0`）：TNIU 流控缓冲、R FIFO、写请求 FIFO、INIU B FIFO，空时各 2 拍。
4. **写协议**：先申请 DBID 再发数据，环上走两趟。
5. **环网本身很快**：站点间纯组合，只有环缓冲（1 拍）和异步桥（约 6 拍）加延迟。

## INIU AR → 上环 15 拍逐拍拆分

| 拍 | 位置 | 做什么 | 源码 |
|---|---|---|---|
| 1 | 低功耗模块 | AR 保持寄存器 | `lwmnoc_iniu_lpctrl.sv:273-293` |
| 2 | 读通道 | AR FIFO（寄存器 FIFO，空时也不直通） | `lwmnoc_iniu_rob_read_channel.sv:76-88` |
| 3 | 拆分器 | 锁存请求（`has_latched`） | `lwmnoc_axi_splitter.sv:259-292` |
| 4 | 拆分器 | stage0：寄存子请求地址和拍数 | `:213-220` |
| 5 | 拆分器 | stage1：**原样寄存，什么都不算** | `:222-229` |
| 6 | 拆分器 | stage2：只算 `axlen = beats-1` | `:231-239` |
| 7 | 拆分器 | 描述符队列 `desc_q` | `:314-345` |
| 8 | 行为映射 | `axi_req_ack` 寄存一拍 | `lwmnoc_upstream_read_behavior_map.sv:94-100` |
| 9 | ROB 表项 | `receive_ar_done` 寄存后才拉起 `tx_req_vld` | `lwmnoc_upstream_read_rob_entry.sv:97-101,129` |
| 10 | INIU | 发送前寄存器切片 | `lwmnoc_iniu.sv:790-802` |
| 11–14 | 异步 FIFO | 写入 1、同步 2、输出寄存器 1 | `fcip_afifo_*_doub` |
| 15 | Top Side | 上环前寄存器切片 | `lwmnoc_iniu_top_side.sv:265-274` |

ROB 模式比 OOO 模式多的 7 拍全部来自拆分器（5）和 ROB 表项（2），而这两处对最常见的"不用拆分的短请求"都不需要。

拆分器的 5 拍是**第一个子请求**的延迟（不是第一个到最后一个子请求）：第 0 拍握手并装载 R0 → 第 1 拍 stage0 → 第 2 拍 stage1 → 第 3 拍 stage2 → 第 4 拍写入 desc_q0 → 第 5 拍经 RS_TYPE=2 切片（valid/payload 组合直通）输出 `m_axvld`。前提是 ROB 表项号已预分配（`entry_id_vld=1`）且 W 长度 FIFO 有空间。拆分时后续子请求每拍一个。

## 优化选项（未实施，等用户决定）

| 改法 | 省 | 代价和风险 |
|---|---|---|
| **A. 拆分器快速通道**：拆分器全空且请求不用拆（≤4 拍或 FIXED）时直接进 `desc_q` | **4** | 只在流水全空时走，不乱序；要拆的请求照走慢路径 |
| **B. 去掉 stage1 空级** | 1（只影响要拆的请求） | 可能是为重定时特意留的，需问设计者（luhz） |
| **C. ROB 表项直通**：分配同拍就参与发送仲裁 | **1–2** | 要保证未寄存的表项不被重复发送，需验证 |
| **D. 低功耗保持寄存器与 AR FIFO 合一**，或 AR FIFO 空时直通 | **1** | 顺带修吞吐问题：`s_arrdy = mode_run && !ar_hold_vld && rd_accept_credit`，背靠背 AR 每 2 拍才收 1 个 |
| **E. 去掉异步 FIFO 后的一个切片**（Top Side 切片改 RS_TYPE=2） | **1** | 取决于到环站的走线时序 |
| **F. 同步时钟模式**：同频同源时参数旁路异步 FIFO | **3** | 新增配置参数 |

A + C + D：15 → 约 9–10 拍；再加 E、F（时钟同源）：约 5–6 拍，低于 OOO 模式的 8 拍。AW 走同一个拆分器，A 对写路径同样有效。曾提议在 lwnoc_mnoc 单独分支上先做 A 和 D 并用 `de/rtl_qc` 现有用例验证——**用户尚未批准**，lwnoc_mnoc 由 luhz 维护，改它之前要先得到同意。

## 拆分器的组合逻辑级数（LOL，粗估）

按 2 输入门等效估算（5 位比较 / 加减 ≈3–4 级，40 位加法 ≈8 级，2 选 1 ≈1 级），参数 ARLEN 4 位、数据 512 位、地址 40 位、ROB 64 项。见 `figures/axi_splitter_pipeline_toy.html`。

| 拍 | 段 | LOL |
|---|---|---|
| 0 | 装载数据（axlen+1、>4 比较） | ≈6 |
| 0 | 装载使能 / `s_axrdy`（经 `child_is_last` + ready 链） | ≈20 + 大扇出 |
| 1 | 子请求字段 → stage0 | ≈16 |
| 1 | **下一地址 / 剩余拍数 R0 → R0 环路**（关键路径，拆分时每拍出一个子请求靠它） | **≈23** |
| 2 | stage1 | 0 |
| 3 | `axlen = beats − 1` | ≈3 |
| 4 | desc_q 入队 / 移位（含 desc_deq） | ≈6 |
| 5 | 表项号对接 + RS2 切片（输出不寄存，下游同拍继续算） | ≈3 |

- `s_axrdy` 是组合输出，跨模块连成一条长组合路径（起点是 ROB 的 `entry_id_vld`）。
- 示例配置 `INIU_AXI_MAX_BURST_LEN=4` 下请求永远不拆，第 1 拍逻辑大部分会被常量化简，但 5 拍延迟照样存在。

## 顺带发现、未确认的问题

- **环缓冲让突发吞吐减半**：almost-full 门限写死为 1（`lwnoc_ring_buf.sv:57`）。文档里有按占用量计算的方案，没实现。
- **环站点可能乱序**：路过的数据在下游 ready 时走直通，优先级高于已排在本站 VC FIFO 里的同 VC 数据，下游 ready 断过一次后后到的可能超过先到的。需 DV 确认。
- **疑似编译错误**：`lwmnoc_default_slv.sv:382-387` 给 `lwmnoc_flow_ctrl_chk` 连了 `clk`/`rst_n`，该模块没有这两个端口。
- **文档与 RTL 不一致**：ROB 模式读数据收齐再发（文档没写）；TNIU 读缓冲结构与文档不同；INIU 写数据 SRAM 的 ECC 是带寄存器的（读出 4 拍），文档说纯组合。
