# 灵活性实验：不规整、由配置驱动的拓扑（specs/TOPO.md）

题目：`topo_noc`，路由器之间的连接是任意无向图，端点挂在路由器上。
- 每个路由器的端口数不同；
- 端口顺序由规则决定；
- 路由表要在展开时用 BFS 最短路径算出来，同距离时取 id 最小的邻居。

路由器统一用给定的 noc_sw：SV 版是 `lib/noc_sw.sv`，UHDL 版是 `lib/router.py`。三种写法各 2 个样本（Opus）：
- **uhdl**：UHDL 生成器；
- **svpy**：Python 模板生成 SV，这是业界常见做法；
- **svpure**：纯 SV，配置只通过 `topo_cfg.svh` 传入（JSON 的逐字转写，`_eval/json2svh.py`），其余全部在 SV 里用常量函数和 generate 推导。

评分：在 A（树）、B（带环的图）和没给过 agent 的 C（环加弦）三个配置上测试，`_eval/grade_flex.py`：
1. 零负载下逐一测试所有节点对，到达位置、数据正确，且延迟等于路由器跳数；
2. 2 万周期随机流量下，和参考实现（`_eval/ref/gen.py`）逐周期比对。

评分脚本自测：同距离时改成取 id 最大的邻居，在 A 上通过（树里不存在同距离），在 B 和 C 上被抓出（约 10.7 万和 8 万处差异）。

源码 token 去掉了注释和空行（o200k 分词）。

- 6/6 全部正确，包括没给过的配置 C。
- **源码量：UHDL 最少。** 比 Python 模板生成 SV 少 30%，比纯 SV 少 35%。
- **总 token 三者打平**（平均 57.8k、55.3k、60.1k）。写代码本身只占开销的一小部分，大头是读规格、自己写测试和仿真。
- **纯 SV 写得出来，Verilator 也能跑，但有工具问题。** 它依赖 unpacked 数组形式的 localparam 和较复杂的常量函数，开源 Yosys 0.51 直接解析失败（packed 多维数组也不行）。要让 Yosys 接受，就得改写成扁平向量加手工切片。商用综合工具的支持情况没有测。
- 纯 SV 的两个 agent 都踩到了 `dist` 是 SV 保留字；其中一个关掉了常量函数里 int 高位未使用的告警。
- UHDL 的一个 agent 发现了一个小毛病：对 `split()` 的结果再切片时，生成的辅助线会带上未使用的位，在 1 位宽的字段上会触发 UNUSEDSIGNAL。

## 结论
1. **"SV 做不到"这个说法不成立。** 纯 SV 在 Verilator 上能做到，Python 模板生成 SV 更是毫无障碍。
2. **但 UHDL 的表达确实最紧凑**：源码比另外两种少 30% 到 35%。在这类设计上，LLM 写 UHDL 的总开销不比 SV 高。
3. **纯 SV 的真实代价在工具链。** 能不能综合，取决于工具对 SV 高级特性的支持程度。UHDL 输出的是展开后的 Verilog-2001，没有这个问题。
4. **Python 模板生成 SV 是 UHDL 真正的对手。** 它同样灵活，只是多了"在字符串里拼 SV"这一层：没有位宽检查，产物是文本而不是可以查询的电路图。这一点这次的测试没能拉开差距，因为题目里规则的部分都由给定的路由器承担了。
