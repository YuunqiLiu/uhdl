# CDC 实验：不规整拓扑 + 多时钟域，测"类型检查"有没有用

## 设计
题目 `specs/CDC_NOC.md`：把不规整拓扑 NoC（topo_core，作为黑盒提供）包成多时钟域。
- 每个端点属于哪个时钟域由配置决定；
- 跨域的数据流必须经过异步 FIFO；
- 每个端点在自己的时钟里计数，计数值要在 NoC 时钟域里读出（多位跨域）；
- 错误标志要汇总到 NoC 域（同一个域里的多个标志要先合并再同步，否则就是重汇聚）。

CDC 规则在规格里以"公司规范"的方式写明，没有逐个信号告诉怎么做。

为这次实验给 UHDL 新增的能力（lwnoc_rewrite 555ad2e / 6038adf）：
- `check_cdc()`：在 UHDL 内部的电路图上做跨域分析，`generate()` 默认会跑；
- 端口可以用 `domain=clk` 声明时钟；
- 三个 CDC 单元：CdcSync、CdcBus、AsyncFifo；
- `s.wire/s.reg/s.mem` 禁止使用 Verilog/SV 关键字作名字。

外部检查器 `tools/cdc_check.py`：基于 Yosys 网表，规则和 UHDL 内置检查完全一致。它既用来给所有方案统一评分，也作为第 3 组的工具。

评分 `_eval/grade_cdc.py`，在配置 A、B 和没给过 agent 的 C 上：
1. **多时钟仿真**（`_eval/make_tb.py`）：4 个互不相关的时钟（100、70、130、230 ps），检查每个 flit 恰好送达一次、按（源，目的）保序、内容完整；统计值不超前、不回退，排空后精确相等；`noc_err` 在稳定时间内跟上；
2. **结构 CDC 检查**。

自测（`_eval/selftest.log`）：
- 参考设计：仿真全部通过，0 违例；
- 4 个错误变体（计数器直接跨域、按位同步计数器、同步器重汇聚、同步器前有组合逻辑）：**仿真全部通过**，但结构检查分别报出 6–9、1–3、1–3、6–9 处违例。

这说明 CDC 错误在 RTL 仿真里看不出来，只能靠结构检查发现。

|---|---|---|---|---|---|---|
| UHDL（内置检查） | Opus | 全过 ×2 | 0, 0 | 1792 / 1838 | 89.3k | 1416s |
| SV + Python，无检查器 | Opus | 全过 ×2 | 0, 0 | 2683 / 2373 | 52.5k | 265s |
| SV + Python + 外部检查器 | Opus | 全过 ×2 | 0, 0 | 2871 / 2948 | 83.8k | 1028s |
| UHDL（内置检查） | Haiku | 全过 ×2 | 0, 0 | 1855 / 1943 | 115.8k | 536s |
| SV + Python，无检查器 | Haiku | 全过 ×2 | 0, 0 | 2669 / 2612 | 99.7k | 590s |
| SV + Python + 外部检查器 | Haiku | 全过 ×2 | 0, 0 | 3027 / 2954 | 125.6k | 1154s |

- 12/12 份有效结果全部功能正确、0 违例，包括没给过的配置 C。
- 另有 1 份 Haiku 的 UHDL 结果作废：那个 agent 跑到了 Opus 的输出目录里，只验证了别人的代码。已在新目录重跑，即上表中的 h_uhdl_c。
- 所有 agent 都选了同一种结构，也就是参考设计的结构：每个方向一个异步 FIFO、计数器走 CdcBus、每个域先合并错误标志再用一个同步器。两个 Haiku agent 把同一个域的所有计数器拼成一个 CdcBus 传过去，这也合规。
- **源码量**：UHDL 比 SV + Python 少约 30%，和上一轮一致。
- **总 token**：无检查器的 SV 组最低。有检查工具的两组（UHDL 内置、SV 外部）都更高，因为这些 agent 做了更多验证：多跑了几组额外配置、反复运行检查。差异主要来自验证投入，不是语言本身。

## 结论
1. **"类型检查能拦住 LLM 的 CDC 错误"这个假设，这次又没有得到支持。** CDC 规则写明之后，Opus 和 Haiku 都一次就做对了，没有任何一处违例需要检查器来拦。这和之前 lint 那几轮的结论一样：只要规则写清楚，当前的模型会照做。
2. **检查器的价值是"保证"，不是"纠错"。** 自测证明，这类错误仿真完全发现不了，只有结构检查能发现。所以在规则没写清楚、代码被很多人和 agent 反复修改、或者需要向审查者证明没有问题的场景里，内置检查仍然有价值。这次的实验没有覆盖这些场景。
3. **UHDL 的内置检查和"SV + 外部工具"在效果上等价**，前提是外部工具的规则一样。UHDL 的优势在于检查默认就开着，不需要额外配置；外部工具还需要一份"端口属于哪个时钟"的映射文件（两个 SV 组的 agent 都自己生成了一份 `cdc_ports.json`）。
